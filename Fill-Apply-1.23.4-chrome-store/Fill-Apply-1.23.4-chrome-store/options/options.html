Adaptive knowledge / Field Memory

Field Memory learns answers you type on unknown application questions and reuses them on similar fields later. Model: Key — Aliases — Type — Value. One Key per meaning; Aliases are wording variants (never separate records). Types: boolean · string · number · date · select · multiselect. User-confirmed answers override built-in. Identity (name, email, phone) stays in Profile settings. Conflicting answers need explicit Keep / Replace / Add alias — never silent overwrite.

Backend / runner

JobPool live mode: uncheck Queue mode and set this URL. The extension GETs /queue and /queue/next, then POSTs /applied/:id with status. Only status=submitted means the employer received the application. Fill / Ready successes are filled / ready. Stop sends POST /cancelled/:id.

How it works

fill never clicks Next/Submit; ready advances multi-step but never final Submit; submit includes final Submit when confidently found. Auto-close only after submit success. Queues: queued → applied / failed / cancelled. Local applied means processed for the current mode — JobPool must read status, not the bucket name.
